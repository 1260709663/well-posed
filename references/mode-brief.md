# 模式一：速览（Brief）

**目标**：让人在 20 分钟内决定"这篇要不要花三天读"。
**篇幅**：4–7 页 PDF。宁短勿长——信息密度高于覆盖面。

---

## 必备结构（严格按序）

### 1. 论文名片

表格，两列。字段：

| 项 | 说明 |
|---|---|
| 标题 | 原文标题，不翻译；副标题保留 |
| 作者 | 全部作者，标注通讯作者（若有） |
| 单位 | 第一作者与通讯作者的单位 |
| 出处 | 期刊/卷/页/年，或 arXiv 编号 + 版本日期 |
| 类型 | 研究论文 / 综述 / 短通讯 / 预印本 |
| 页数·定理数 | 如 38 页，含 4 个主定理、11 个引理 |
| MSC / 关键词 | 原文给出的分类号 |
| 对象方程 | 用一句话写出被研究的方程本身（带公式），如"三维不可压 Navier–Stokes：$\partial_t u+u\cdot\nabla u=-\nabla p+\nu\Delta u$" |

### 2. 一句话结论

**恰好一句话，不超过 3 行**，套这个句式（按需调整）：

> 针对【问题】，在【关键假设】下，用【方法】证明了【结果】，相比【已有最好结果】把【某个指标】从 A 改进到 B，但【局限】。

这一句写不出来，说明还没读懂，回去重读引言最后两段。

### 3. 主要定理清单（本文的核心价值）

2–6 条。**每条必须完整陈述**，用 `thmbox`，标题写原文编号：

```
\begin{thmbox}{定理 1.2 \refo{(p.4, Theorem 1.2)}}
[完整数学陈述：假设 + 结论，指标、常数依赖、维数范围全部写全]
\end{thmbox}
```

每条定理后紧跟一行小字（`\small\color{notecolor}`）：

- **靠什么证**：3–6 个词点出技术核心（如"Strichartz 估计 + 剖分迭代"）。
- **强在哪**：与已有结果差在哪个指标。

**禁忌**：
- 不许写"作者证明了全局存在性"这种无内容概括。
- 不许改弱假设——若原文假设 $s>1/2$，写成 $s>0$ 是硬错误。
- 定理若分情形（$d=2$ / $d\ge 3$），必须分开写。

### 4. 论文骨架

用 6–12 行展示逻辑依赖链，不是目录罗列。格式：

```
§1 引言：提出 XX 猜想，指出已有方法的瓶颈在于 ___
§2 预备：建立 a priori 估计 (2.14)，这是全文的地基
      ├─→ §3 用它 + 紧性方法得到弱解存在
      └─→ §4 用 (2.14) 的量化版本做唯一性
§5 强解：额外假设 u_0 ∈ H^2，用 bootstrap 提升正则性
```

能画出依赖箭头就算达标。

### 5. 方法与技术路线

- **工具箱**：把方法归类到 PDE 常见范式（能量估计 / 单调算子 / Galerkin / 紧性方法 / 补偿紧性 / Strichartz / 色散估计 / 调和分析（Littlewood–Paley、极大函数）/ 熵–耗散 / 相对熵 / Monge–Ampère 型 / 变分与 $\Gamma$-收敛 / 粘性解 / 随机分析 …）。
- **技术核心**：指出**哪一步真正难**，以及作者怎么绕过去的。这是速览里最值钱的一段，写 5–10 行。
- **可迁移性**：这个方法能不能搬到相邻问题？一句话判断。

### 6. 结果强度评估

小表对比，3–5 行，对象是本文 vs 引言中提到的 2–3 个已有结果：

| 结果 | 假设 | 结论（正则性/维数） | 是否最优 |
|---|---|---|---|
| [12] (2019) | $d=2$，$C^2$ 区域 | 全局弱解 | — |
| 本文 Thm 1.1 | $d\le 4$，Lipschitz | 全局弱解 + 唯一性 | 唯一性最优，正则性非最优 |

若作者声称 optimal，用 scaling 论证粗核一遍：把 $u_\lambda(x,t)=\lambda^{\alpha}u(\lambda x,\lambda^{\beta}t)$ 代入方程，看指标是否保持不变。核不出来就写"未核验"。

### 7. 期刊水平

照 `sources.md` 的规范：中科院分区 + JCR + 领域口碑三行，全部带来源与查询日期。若是预印本，先查是否已见刊。

### 8. 作者介绍

每位作者 3–4 行：单位、阶段、主攻方向、2 篇代表作、与本文的关系（是否长期做这条线）。表格或紧凑列表都行。

### 9. 读法建议（收尾）

三选一，并说明理由：

- **只需知道结论**：读 §1 + 定理陈述即可，本文技术无迁移价值。
- **读方法**：建议读 §2–3，跳过 §4 的技术性估计。
- **值得全文精读**：方法有迁移价值 / 是该方向的关键节点，建议转模式二。

---

## 写作风格

- 中文正文，术语保留英文原词并在首次出现处给中文（"紧性方法（compactness method）"）。
- 判断句要敢下结论："这一步我认为有漏洞""该结果在 $d=3$ 情形实际不成立"，但要给出理由。
- 不复制摘要的修辞（"we establish a striking new framework" 之类），只写事实。
